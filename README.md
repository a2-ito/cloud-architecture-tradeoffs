# cloud-architecture-tradeoffs

AWS / Google Cloud / Cloudflare で、よくあるアーキテクチャパターンをどう組むか、
そのとき何を得て何を捨てるかを整理する。

## 目的

- 同じ要件を 3 つのクラウドでそれぞれどう実現するかを並べる
- 「どれが一番いいか」ではなく、選んだときに何を引き換えにするかを書く
- 判断の前提（規模、レイテンシ要件、コスト、運用体制など）を明記する

## 対象

| クラウド | 特徴 |
| --- | --- |
| AWS | サービスが最も多く、リージョン単位で組み立てる |
| Google Cloud | マネージドなデータ基盤とグローバルなネットワークに強い |
| Cloudflare | エッジ（利用者に近い拠点）で動かす前提で組み立てる |

## 書き方

1 パターンにつき 1 ファイル。
クラウドごとのディレクトリに置き、複数のクラウドにまたがる比較は `cross-cloud/` に置く。
各ファイルは次の順で書く。

1. 解きたい課題と前提
2. クラウドごとの構成
3. トレードオフ（性能、コスト、運用負荷、ロックイン）
4. 選ぶ基準
